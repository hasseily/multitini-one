# MiSTer Game Boy Import Record

Status: 47 allowlisted files imported, SHA-256 locked, and listed in the
license ledger. Portable firmware and HDL tests pass. PSRAM-enabled build
`2026090E` passes the Vivado 2025.2/Vitis 2025.2 flow and its first board
tests: the supervisor switched from C64 to GBC and Tomb Raider and V-Rally ran

## Product boundary

The Multitini build uses the Game Boy/Game Boy Color machine, mapper, video,
audio, timer, DMA, and T80 dependencies. It does not import the MiSTer platform
top, Intel PLL/SDRAM wrappers, releases, borders, palettes, screenshots, binary
boot ROMs, or game cartridges.

`third_party/gameboy/import_manifest.json` is the exact allowlist. The selected
first adapter supports:

- GB and GBC cartridges from 32 KiB through 8 MiB;
- one eight-button gamepad;
- raw RGB555 video expanded to RGB888;
- stereo audio sampled onto the common 48 kHz event stream; and
- the open SameBoy-derived CGB bootstrap, with an optional exact-size run-time
  override.

SGB, MegaDuck, camera UI, link cable, cheats, rewind, savestates, borders, and
persistent RTC/save handling are outside the first adapter. Mapper logic stays
close to upstream even where those optional services are disabled.

## Local compatibility ports

The exact upstream `rtl/gb.v` and `rtl/cart.v` files remain imported and locked
as references. The product manifest builds deterministic ports generated by
`scripts/port_gameboy_core.py`:

- `hdl/core/gameboy/ports/gb.v` selects the generated open bootstrap memory,
  moves declarations before use for strict tools, and replaces fabric-gated
  CPU/RAM clocks with clock enables on the machine root clock;
- `hdl/core/gameboy/ports/cart.v` moves mapper-facing declarations before use;
- `hdl/core/gameboy/ports/cheatcodes.sv` gives procedural outputs and working
  variables explicit SystemVerilog variable types and moves parameters before
  their use in port widths;
- `hdl/core/gameboy/ports/gbc_snd.vhd` expresses the DAC decay period as the
  declared scalar range bound for Vivado compatibility;
- `hdl/core/gameboy/ports/megaswizzle.sv` gives its combinational outputs
  explicit SystemVerilog variable types;
  and
- `hdl/core/gameboy/ports/dpram.sv` replaces Intel dual-port RAM primitives
  with explicit Xilinx block-memory instances that retain the registered
  address latency, write-first behavior, asymmetric bootstrap geometry, and
  CPU-side clock enable.

The product bootstrap memory file is generated from the pinned MIF by
`scripts/generate_gameboy_bootrom.py`. Both artifacts are allowlisted by the
repository content check and covered by the upstream MIT notice and source.

## Memory path

The cartridge loader writes aligned 64-bit lines into the common memory
request/response service. A one-line core-side cache stalls Game Boy clock
enables on a miss or external cartridge-RAM write. The board wrapper contains
a control-to-machine CDC bridge and a prepared Appletini PSRAM PHY path.

The board service packs each logical eight-byte line as four bytes in each of
the two parallel x4 devices. Its physical address is the aligned logical
address divided by two. This is not optional bookkeeping: passing the logical
address through would place cartridge RAM at physical `0x800000`, outside the
LY68L6400 A[22:0] range, where it can alias and corrupt cartridge ROM. Boundary
regressions cover the largest ROM line and first cartridge-RAM line.

`ENABLE_GBC_PSRAM` defaults to zero, so the physical PSRAM pins remain inactive.
The earlier default-off build passed mixed-language elaboration, XPM
block-memory mapping, routing, CDC, DRC, timing, bitstream, XSA, Vitis
application, and Bootgen packaging gates. A usable cartridge image must set
`MULTITINI_ENABLE_GBC_PSRAM=1`. The `2026090E` opt-in image passes those vendor
gates with +0.211 ns setup and +0.055 ns hold slack. Its installed package
loaded Tomb Raider (MBC5+RAM+battery, 4 MiB) and V-Rally (MBC5, 1 MiB), and
both ran into gameplay on the connected board. A broader mapper matrix,
save-data persistence, RTC behavior, input, audio, and repeated switching
remain open.

The routed default-off GBC build uses a 33.558 MHz machine clock, 6,989 LUTs,
6,000 flip-flops, 13 RAMB36 blocks, five RAMB18 blocks, and two DSP blocks. It
passes with +1.394 ns setup slack and +0.055 ns hold slack. The build flow also
rejects any fabric LUT that drives a clock pin; CPU and RAM cadence use clock
enables on the machine root clock. That routed result predates the current
display integration. Current source publishes exact 160x144 frames through a
four-bank RGB565 Gray-pointer ring, then scales them 6x to a centered 960x864
image in the common 1080p output. The frame bridge, cartridge service, GB/GBC
validation, shared USB gamepad path, and keyboard fallback pass portable
tests. The default-off PSRAM build still has no cartridge-memory backing for a
physical game run.

No proprietary Nintendo boot ROM is required. The product image contains the
pinned open SameBoy-derived CGB bootstrap. The user supplies only a `.gb` or
`.gbc` cartridge under `0:/multitini/cores/gbc/media`.

## Reproducible gates

Audit a checkout at the pinned commit with:

```sh
python3 scripts/audit_gameboy_import.py --source /path/to/Gameboy_MiSTer
```

Check the staged source and deterministic ports with:

```sh
python3 scripts/audit_gameboy_import.py
python3 scripts/generate_gameboy_bootrom.py --check
python3 scripts/port_gameboy_core.py --check
python3 scripts/check_repo.py
./scripts/lint_gameboy_sv.sh
```

Use `--update-lock` only while intentionally restaging the pinned allowlist.
