# C64 disk launch candidate 20260915

This records the 20260915 candidate. The later Ultima II board report and
firmware-only launcher change are in [C64_LAUNCH_20260916.md](C64_LAUNCH_20260916.md).

## Board report on 20260914

The user reports that Decathlon works with Mount & Run. Colors disk 1 stays
on the blue BASIC screen showing READY/RUN. Fast ROMs and CPU turbo were Off.
With fast ROMs On, Colors instead reports that the drive must be turned on.
UART reports ABI 0.10, build 20260914, status `000001CD`, error `00000010`,
and a mounted, writable, clean D64 with no ARM media-service fault.

The user also reports that the fast loader otherwise works well and that
battery saving works. These are initial functional passes, not long-run,
power-loss, or all-game qualification. Colors remains a compatibility failure.

## Findings

- The browser accepted only files loading at `$0801`. The local Ultima I disk
  has 22 closed PRGs with valid chains. `ULTIMA I` loads at `$02A7`; it changes
  BASIC's main-loop vector, loads `HELLO`, restores that vector, and jumps to
  `$0810`. `HELLO` loads at `$0801` but has an empty BASIC header. Direct RUN
  is not its intended start path.
- A stock-ROM CPU/1541 simulation of `LOAD"ULTIMA I",8,1` reaches the bootstrap
  and then the HELLO entry without an injected RUN or SYS. This checks the
  loader sequence, not video or gameplay.
- Colors has a valid 849-byte PRG containing `10 SYS2064`. Both native LOAD
  followed by RUN and the existing direct-RAM stage reach its custom loader
  in the CPU/1541 model. Both later wait for IEC clock / disk SYNC. The model
  has drive/video limitations; this does not identify the physical hang.
- A separate HDL regression reproduces disk-ID corruption on cache hits.
  The GCR encoder used the last ARM request's LBA to decide whether incoming
  bytes belonged to directory track 18. A cached copy does not make an ARM
  request, so unrelated cached data could replace the disk ID. The fix uses
  the track actually being copied. Both stale-LBA directions are tested.
- The staged PRG reset also resets the 1541 through `core_enable`. An
  integrated HDL trace observed 256 reset clocks and release during BASIC
  startup. A surviving drive program is not supported as the cause.

The disk-cache bug is proven. Its connection to the Colors hang is unproven.
`CORE_READY` plus `CORE_LOAD_ERROR` in the user log is consistent with the
adapter's nonfatal drive-error path; it does not establish a missing Return.

## Changed behavior

The Mount & Run browser includes closed PRGs whose complete chain and memory
range validate. Entries needing the native drive path show `[drive load]`.
Enter directly installs and RUNs a nonempty linked BASIC program at `$0801`.
Other entries use the actual drive and `LOAD"name",8,1`, leaving autostart to
the program. Arbitrary machine-code entry points are never guessed.

Right selects native drive loading for any listed entry. It sends no RUN or
SYS afterward. A BASIC program loaded this way needs a manual RUN. Names that
cannot be typed exactly, include DOS metacharacters, or are ambiguous in the
full PRG directory are refused before reset or eject. No filename approximation
is used. Unsupported names remain visible.

Native loading first flushes/ejects the disk, waits for a fresh BASIC session,
remounts the same disk, and types the command with input events. Disk service
continues between key events. A failed remount does not send the command or
arm a deferred RUN of the empty BASIC session.

## Board retest

1. Install the candidate supervisor firmware and all three candidate C64
   package files. GBC needs no update. Verify UART firmware and active C64
   shell build `20260915`, ABI `0000000A`.
2. Keep Fast serial ROMs and CPU turbo Off. Mount the Ultima I disk and open
   Mount & Run. Confirm `ULTIMA I [drive load]` and the other valid PRGs appear.
3. Select `ULTIMA I`, press Enter, then close F12. The C64 should type
   `LOAD"ULTIMA I",8,1`. Allow up to a minute for the normal disk load. Do not type
   RUN or SYS; the original bootstrap controls startup.
4. Repeat Decathlon Mount & Run to check the direct BASIC path.
5. Repeat Colors Mount & Run with Enter. Capture the full launch log and then
   UART `s` and `:disk` if it hangs.
6. For a native-path comparison, restart C64, open the Colors program list,
   select its PRG and press Right. Close F12. After LOAD returns READY, type
   RUN. Capture the same output if it hangs. Native loading is a diagnostic
   comparison, not a promised Colors workaround.
7. Repeat the relevant tests in NTSC using programs compatible with that mode.

No candidate board result is recorded yet.
